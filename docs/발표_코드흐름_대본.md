## 0. 처음 화면

사용자가 `http://127.0.0.1:8000/`에 들어오면, `config/urls.py` 8번째 줄의 `include`가 요청을 `project10/urls.py`로 넘기고, 5번째 줄 `path('', views.index)`가 **`views.py`의 `index` 함수**로 연결합니다.

`index` 함수는 DB에서 작업 기록을 꺼내, 16번째 줄 `render(..., {"jobs": jobs})`로 **`index.html`에 `jobs`라는 이름으로 넘기고**, `index.html` 121번째 줄 `{% for job in jobs %}`가 **그걸 받아서** 표를 그립니다.

## 1. 프론트 → Django

사용자가 버튼을 누르면 **`analyze.js` 34번째 줄 `fetch`가** 영상을 보냅니다.

보낼 주소는 `index.html` 99번째 줄 `data-api="/analyze/"`에 적혀 있고, `analyze.js` 17번째 줄이 이 주소를 꺼냅니다. 영상은 `index.html` 103번째 줄의 **`name="video"`라는 이름표**에 담겨 multipart 형식으로 갑니다.

## 2. Django 안에서 주소 찾기

요청을 받은 Django는 `settings.py` 53번째 줄 **`ROOT_URLCONF`** 설정대로 `config/urls.py`부터 봅니다.

`config/urls.py` 8번째 줄 `include`가 **`project10/urls.py`로 넘기고**, `project10/urls.py` 6번째 줄 `path('analyze/', views.analyze)`가 **`views.py`의 `analyze` 함수로 연결**합니다.

## 3. Django A: 받기, 검사, 저장

**`views.py` 20번째 줄 `analyze` 함수가 요청을 받습니다.**

22번째 줄 `request.FILES.get("video")`가, 프론트가 `name="video"`로 보낸 **영상을 같은 이름으로 꺼냅니다.**

검사를 통과하면 33번째 줄 `AnalysisJob.objects.create()`가 **영상은 `media/uploads/`에, 작업 기록은 `db.sqlite3`에 저장**합니다. 이때 상태는 `PENDING`입니다.

## 4~5. Django A → Django B → FastAPI

저장한 작업(`job`)은 **`views.py` 35번째 줄 `run_prediction(job)`이 `services.py`의 `run_prediction` 함수로 넘깁니다.**

**`services.py` 18번째 줄 `run_prediction`이 받아서**, 23번째 줄에서 저장된 영상을 열고, 24번째 줄 **`requests.post`로 FastAPI의 `/predict/video`에 보냅니다.** 이때 이름표는 `"file"`입니다.

## 6. FastAPI가 받음

FastAPI는 **켜질 때 `main.py` 13번째 줄 `load_model_bundle()`로 모델을 한 번 불러 둡니다.**

**`main.py` 29~30번째 줄 `@app.post("/predict/video")`의 `predict_video` 함수가** Django가 `"file"`로 보낸 영상을 **`file`이라는 같은 이름으로 받습니다.** 임시 파일로 저장한 뒤, 37번째 줄에서 **`pipeline.py`의 `analyze_video`로 넘깁니다.**

## 7. FastAPI 추론 파이프라인

**`pipeline.py` 167번째 줄 `analyze_video`가 영상 경로를 받아**, 네 함수에 차례로 넘깁니다.

- 171번째 줄: `read_video`가 영상을 받아 **프레임 목록**을 돌려주면
- 172번째 줄: `extract_keypoints`가 프레임을 받아 **관절 좌표**를 돌려주고
- 173번째 줄: `make_features`가 관절 좌표를 받아 **1,140개 특징**을 돌려주고
- 174번째 줄: `predict`가 특징을 받아 Random Forest로 **동작과 신뢰도**를 돌려줍니다.

176번째 줄 `return`이 이 결과를 `predictions` JSON으로 만들어 **Django에 돌려줍니다.**

## 8. FastAPI → Django B

**`services.py` 31번째 줄 `res.json()`이 FastAPI의 JSON을 받고**, `_pick_first`가 첫 번째 사람 결과를 꺼냅니다.

동작과 신뢰도를 `job`에 채우고, 35번째 줄에서 상태를 `SUCCESS`로(오류면 39번째 줄에서 `FAILURE`로), 41번째 줄에서 처리 시간을 넣은 뒤, **42번째 줄 `job.save()`로 DB에 다시 저장**합니다.

## 9. Django A → 프론트

다시 `views.py`로 돌아와서, **38번째 줄 `JsonResponse`가 채워진 `job`의 값 6개를 JSON으로 프론트에 보냅니다.**

## 10. 프론트가 받아서 표시

**`analyze.js` 40번째 줄 `res.json()`이 그 JSON을 받습니다.**

성공이면 48번째 줄 **`addRow(job)`이 받은 값으로**, `index.html` 118번째 줄의 표(`id="job-rows"`) 맨 위에 한 줄을 추가합니다. 실패면 44번째 줄 `showError`가 `index.html` 95번째 줄의 빨간 상자에 문구를 보여줍니다.

## 이름표가 맞아야 하는 곳 (질문 대비)

발표 중 "왜 연결되나요?"라고 물으면, **보내는 쪽과 받는 쪽의 이름이 같기 때문**이라고 답한다.

| 보내는 쪽 | 받는 쪽 | 맞춘 이름 |
|---|---|---|
| `index.html:103` `name="video"` | `views.py:22` `FILES.get("video")` | `video` |
| `index.html:99` `data-api="/analyze/"` | `project10/urls.py:6` `path('analyze/')` | `/analyze/` |
| `services.py:24` `files={"file": ...}` | `main.py:30` `file: UploadFile` | `file` |
| `services.py` `FASTAPI_URL` | `main.py:29` `@app.post("/predict/video")` | `/predict/video` |
| `pipeline.py:176` `"predictions"` | `services.py` `_pick_first` `data.get("predictions")` | `predictions` |
| `views.py:38` JSON 키 6개 | `analyze.js` `addRow` `job.id` 등 | 키 6개 |
| `views.py:16` `{"jobs": jobs}` | `index.html:121` `{% for job in jobs %}` | `jobs` |

## 한 문장 요약

> "`analyze.js`의 `fetch`가 `video`로 보내면 → `views.py`의 `analyze`가 받아 저장하고 → `services.py`의 `requests.post`가 `file`로 보내면 → FastAPI `main.py`의 `predict_video`가 받아 `pipeline.py`로 예측하고 → JSON을 `services.py`가 받아 저장한 뒤 → `views.py`의 `JsonResponse`로 보내면 → `analyze.js`의 `addRow`가 받아 표에 그립니다."

## 10번 다음에 0번인가?

아니다. **10번 다음에 0번으로 자동으로 돌아가지 않는다.** 0번은 처음 화면을 열 때만 실행되고, 버튼을 누르는 흐름(1~10번)과는 따로 움직인다.

```
[페이지를 열 때 / 새로고침할 때]   0번만 실행 (GET /)
                                  → DB 기록을 꺼내 표 전체를 그림

[버튼을 누를 때마다]              1 → 2 → … → 10 실행 (POST /analyze/)
                                  → 표 맨 위에 한 줄만 추가
```

### 10번이 끝난 다음

| 사용자가 하는 일 | 실행되는 것 |
|---|---|
| 아무것도 안 함 | 아무것도 실행 안 됨. 화면은 10번에서 추가한 줄이 보이는 상태로 그대로 있음 |
| 다른 영상으로 버튼을 다시 누름 | **1번부터** 다시 시작 (0번은 건너뜀) |
| 새로고침(F5) | **0번** 실행. DB에서 방금 저장된 기록까지 포함해 표 전체를 다시 그림 |

### 왜 이렇게 나눴나

- 10번의 `addRow`는 **새로고침 없이** 한 줄만 끼워 넣는다(fetch 방식). 그래서 0번을 다시 부를 필요가 없다.
- 10번에서 추가한 줄도 이미 8번 `job.save()`로 DB에 저장돼 있어서, 나중에 새로고침하면 0번이 DB에서 꺼내 똑같이 보여준다. 그래서 **새로고침해도 기록이 사라지지 않는다.**

### 발표에서 말할 문장

> "0번은 페이지를 열 때 한 번, DB에 저장된 기록 전체를 보여주는 단계이고, 1번부터 10번은 버튼을 누를 때마다 반복되는 단계입니다. 버튼을 누른 결과는 새로고침 없이 표에 바로 추가되고, DB에도 저장되기 때문에 새로고침하면 0번이 그 기록까지 다시 보여줍니다."
